# Every version pinned exactly (Day-7 remediation, finding S13).
# `psycopg2-binary` previously used `>=`, so two builds of the same commit could
# install different code -- a reproducibility and supply-chain problem, and it
# made the dependency audit a moving target. Each pin matches a version this
# suite was run against.
#
# The resulting set is clean under `pip-audit`: "No known vulnerabilities
# found", zero waivers. The CI security-scan step now gates on that; it used to
# run `pip-audit --desc || true` with continue-on-error, so a green build once
# reported 37 known vulnerabilities across 5 packages.
# ---------------------------------------------------------------------------

# Web layer. fastapi 0.115.0 -> 0.142.2 moves starlette 0.38.6 -> 1.7.0,
# clearing the advisories on the old pin; uvicorn is bumped with it because it
# is the server that actually runs starlette. All 59 pre-existing tests passed
# on the new pair before any application code was touched, which is the point of
# bumping the framework separately from changing behaviour.
fastapi==0.142.2
uvicorn[standard]==0.54.0
pydantic==2.9.2
pydantic-settings==2.5.2
email-validator==2.2.0

# Data layer. Unchanged: no advisories, and alembic migrations here are
# verified against a live Postgres by the CI `postgres-migration-check` job, so
# churn without a reason would be churn without evidence.
SQLAlchemy==2.0.35
alembic==1.13.3
psycopg2-binary==2.9.13

# Auth. PyJWT replaces python-jose[cryptography]==3.3.0 (finding S2):
# python-jose carried PYSEC-2024-232/233 plus PYSEC-2025-185, which has no
# published fix, and the project is effectively unmaintained; it also pulled in
# `ecdsa`, which has an unfixed advisory of its own. The API surface used was
# two calls and one exception type across four modules, so the migration is
# exact -- see the comment in app/core/security.py.
PyJWT==2.15.1
passlib[bcrypt]==1.7.4
bcrypt==4.0.1
# 0.0.9 -> 0.0.32 (finding S4). Required because /auth/login declares
# OAuth2PasswordRequestForm, which FastAPI refuses to import without it. Note
# the precise exposure: the advisories concern multipart/form-data parsing, and
# no endpoint here accepts a file upload -- login posts urlencoded form data --
# so unlike the sibling CertiFake (which parses untrusted uploads at
# api.py:46,177,282) these were not reachable through a request this app
# accepts. Bumped anyway, because "not reachable today" is not a reason to keep
# a vulnerable pin.
python-multipart==0.0.32

# Caching and background jobs. Unchanged: no advisories.
redis==5.0.8
celery==5.4.0
fakeredis==2.26.1
